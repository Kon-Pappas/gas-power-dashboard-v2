# Decisions log

Format: **what** · *why* · alternatives rejected. The log starts on 26 October 2026, the day the alignment of this dashboard with the other hub dashboards began (house style as in live-greekpower and Flows; it is handled in its own thread, one phase at a time). Decisions marked *(existing)* were taken earlier, while the dashboard was built; they are written down here so that they are not lost.

| # | Decision | Why / what was rejected |
|---|---|---|
| D01 | *(existing)* **Cost model.** The theoretical cost of a unit is calculated **hour by hour** from its SCADA output: the position of the output between the unit's technical minimum and maximum (`PLANT_SPECS`) gives, by linear interpolation, that hour's efficiency and CO₂ factor; fuel cost = HGSIDA ÷ efficiency × MWh, CO₂ cost = tonnes × EUA price. Everything is calculated in `update_data.py` (`process_economics`) and stored in `daily_economics`; the page only shows it | Python calculates, the page only shows (hub rule). Linearity is the main simplifying assumption, written in the Methodology modal: real heat-rate curves are not linear and no per-unit curves are public. Rejected: one flat efficiency per unit and day (hides that a unit near its minimum is much less efficient). |
| D02 | *(existing)* **CO₂ price.** EUA price from oilpriceapi.com (`OILPRICE_API_KEY`), **one call per daily run** (`/v1/prices/latest`), stored under today's date; a backfill never calls the API. A weekend takes the last real price, marked `Estimated`; with no real price at all the value is €85.00, also marked. The page shows an *estimated* badge (Greek / English). 1 Jun – 23 Aug 2026 is the flat €85.00 estimate | Free tier: 50 requests a month, historical data not included; the older by-date lookup is not documented by the provider and gave shifted or repeated prices, so it was dropped. The price of the latest call may be the previous close, written under today's date: a known simplification. Rejected: scraping a market-data site for the missing history (terms of use forbid redistribution). |
| D03 | *(existing)* **Economics wait for HGSIDA.** The economics of a day are written only when a real HGSIDA > 0 exists for it; otherwise they wait for the next run. **Measured 26 Oct 2026 (git history of `main`, days 9–24 Oct):** the HGSIDA of day D first appears in the midday run of day **D+1**, between 11:00 and 12:42 (13:28–14:44 on 10–12 Oct), and never in the 07:07 run. **26 Oct 2026:** the manual run of 09:44 already had the HGSIDA of 25 Oct, which the 07:07 run did not: on that day it appeared between 07:07 and 09:44 (the other days only show the time of the run that first saw it) | HEnEx writes the file with the headers before the values: a day with HGSIDA = 0 gave a fuel cost of 0 and a fleet SRMC of 35 instead of 155 €/MWh (found 1 Oct 2026). Hence the midday run (D07). |
| D04 | *(existing)* **Generic constraints.** From the last sheet of the ISP2 file (*GenericConstraints*) only the unit and the hours are kept (`daily_gas_constraints`), for gas units on a **list of allowed prefixes**; Alouminio (co-generation, locked 24/7 output), Ptolemaida5 (lignite) and Agras (large hydro) are always left out. The MWh are the hourly SCADA of the unit inside those hours. A day without SCADA is left out of the Surplus chart and its totals; a day with SCADA and no constraint, or a low surplus, stays in, shown as zero | A list of what is allowed (not of what is excluded) keeps lignite and hydro out whatever appears in the file. ISP2 is the reference: ISP3 does not cover the whole day. The 56 rows of Elpedison that matched no SCADA unit were fixed in late September 2026 (they had added up as zero). |
| D05 | *(existing)* **Daily surplus** = the *Energy Surplus* row of the ISP2 file (column TOTAL, absolute value), stored in `daily_surplus` | It is a schedule, not a measurement; the Methodology says so. |
| D06 | *(existing)* **Unit classes** (H-Class, F-Class, Peakers) come from `thermal_efficiency` and decide the order and colour of the units in Daily Overview | One reading of the fleet by technology, as in the economics. |
| D07 | **Updates only from cron-job.org, daily at 07:06 and 13:00 Greek time (Europe/Athens, both jobs).** The workflow has no `schedule:`. The 13:00 run exists because of HGSIDA (D03) | **Measured 26 Oct 2026 (git history, 9–24 Oct):** the SCADA of day D was in `main` at the morning run (07:07–07:08) of D+1 on 15 of 16 days (22 Oct: 14:24). The GitHub `schedule` (`0 4 * * *`) drifts, and since the clock change of 25 Oct it would start at 06:00 Greek time, before the SCADA is published (~06:05). 13:00 leaves margin after the 11:00–12:42 appearances of D03. Rejected: keeping `schedule:` as a backup (it runs before the SCADA and adds commits); a third run (revisit if a late SCADA like 22 Oct repeats). |
| D08 | `data/meta.json` holds `fetched` (time of the run) and `next_update` (next scheduled run), both UTC with `Z` as in BESS and Flows (hub D06). The next run is computed in Athens time from `UPDATE_SCHEDULE` in `update_data.py`, so it is correct across the clock changes (tested 24–25 Oct 2026 and 27–28 Mar 2027). Its only writer is `update_data.py`, after the data file; the page shows both in Athens time and "-" if the file is missing | **Before (26 Oct 2026):** the page took the latest data date + "08:00" as *Last update* (showed 25/10/2026 08:00) and the next day + "08:00" as *Next* (26/10/2026 08:00): neither was the real run time. Python calculates, the page only shows. |
